## Separate quantities

For each supported native module, the original effective update is `D = alpha_scale * B @ A`. A block magnitude is the square root of the sum of its module squared norms. It is a measurement, not an editable loader setting. Current multipliers `m` and model strength `s` give adjusted block magnitude `abs(s*m)*norm(D)`. Stacked updates add independently; signed inner products describe reinforcement/cancellation in parameter space. Neither norms nor cosine alignment establishes image quality or semantic influence.

Original measurements must never be turned directly into normalized loader multipliers. The original setting is multiplier 1 on present blocks, 0 on absent blocks. Original measurements, saved settings, computed suggestions and personal revisions must remain separately identifiable. One server-owned proposal supplies display, copy and persistence, with fresh loader coverage checks before Copy.

## First working recommendation prototype

`role_measured_start_v1` reads roles from pinned saved profiles, including personal overrides. It declares the following editable preferences: character/person, clothing/coat/footwear and pose start Protect; style/lighting start Flexible; environment, utility and unknown intent start Normal. These rules determine which contribution may yield, not which blocks mean face, shoes or jacket. Equal priorities stay unchanged. Explicit owner priority overrides take precedence. Unknown roles are shown and use Normal rather than guessed semantic profiles.

For this first prototype, reuse the previously tested signed effective-update adjustment: positive pair pressure above 0.5 permits at most a 20% reduction of the lower-priority multiplier. Use the full original magnitudes and signed inner products; do not average profiles or impose normalized role energy quotas. BASE, zeros, signs, supporting strengths and protected contributions are retained. Revert a proposed block change if it increases the full signed combined update energy. A no-change result is a valid unresolved result, never a successful repair claim. The threshold is not lowered to force changes.

This is deliberately a conservative, role-informed measured trial, not yet the complete calibrated role-shaped profile system from the older conversation. In particular, protecting both identity and clothing can leave their clash unresolved. Owner-rendered acceptance and saved personal rules are needed before adding stronger starting envelopes or block semantic claims.

Every proposal records role rules, overrides, before/after multipliers, original and adjusted magnitudes, candidate intervals and reasons. The existing immutable experiment transaction retains the complete receipt and exact parent versions; no Default is overwritten.

## One graph

The graph has one contribution scale: original measured shape as a distinct line, adjusted contribution as bars, and exact editable multipliers in a single aligned numeric row. A fixed per-LoRA plot scale shared by line and bars must not change during an edit. Original-relative normalization is allowed for display only, never computation. Negative multipliers need a visible sign. Zero-update/absent blocks cannot gain content by increasing a multiplier.

Colour guidance distinguishes inactive, protected by the selected experiment, suggested for an explained trial, and review required. It does not claim safe/unsafe semantic bands. Suggested intervals are policy trial bounds, not architectural limits. Reset one block to original setting, reset all settings to original, and restore the computed suggestion are separate non-destructive actions.

## Saved combinations and library changes

Automatically retain a computed baseline separately from personal variants. Match reuse against ordered stable LoRA/source identities, target/loader contract, saved input versions and strengths, roles, priority choices, measurement engine and policy version. Reusing stored numbers still requires fresh source and export validation. A preferred personal variant is an explicit-load shortcut and does not automatically override the displayed computed baseline. Recompute creates a new baseline; prior personal variants remain selectable and are marked for review when their context changes.

Library root selection, initial/manual scans and checks when reopening the app must preserve file/history identity. Show added, missing and changed files clearly. Moving a folder must not silently lose saved profiles or bind them to a different file. Existing server-startup scans are retained; browser reopen freshness is additional work.
